# Add Hidden-Gem Restaurants (Málaga & Marbella) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add API-verified hidden-gem restaurants to the Málaga and Marbella zones of `index.html`, using the identical data pipeline and schema as existing entries.

**Architecture:** Add 20 researched candidates to `fetch-places.mjs`'s `PLACES` list → re-run the fetch to (a) regenerate `places-data.json` and (b) reveal each candidate's real rating/review-count → keep only spots passing the gate (rating ≥4.4 AND reviews ≥100) → write those as bilingual food entries in the correct zone's `food:[]` array → re-fetch once more so `PLACES_DATA` in `index.html` includes them → browser-verify → push.

**Tech Stack:** Node 18+ (native fetch), vanilla JS single-file site, Google Places API (New).

## Global Constraints

- **The API key must never appear in `index.html`, `places-data.json`, or git history.** Key read from `process.argv[2]` as `"$(cat gcloud.secret)"`.
- **Verification gate:** keep a candidate only if the Places API returns `rating >= 4.4` AND `userRatingCount >= 100` AND the returned name plausibly matches the candidate (not a same-named place elsewhere). Drop and report others.
- **Schema (exact):** every new food entry is `{n:[de,en], tier:"street"|"mid"|"splurge", closed:[...], d:[de,en], meta:[de,en] or "string", url:"..."}` — bilingual, matching existing entries.
- **Voice:** descriptions terse, specific, opinionated, matching neighbouring entries' tone; DE and EN.
- **Additive / no regressions:** existing entries and all render machinery (`dataFor`, `catFor`, `chips`, `mapBtn`, `foodCard`, `openSheet`) are untouched.
- **Guardrails:** the user's $1 budget alert + key-restriction are already set (prior session). One re-fetch ≈ ~250 calls, within free tier.
